# Teaching rules for this project

This repository is both an operating-system implementation and a book that builds
the reader's knowledge from zero. Every lesson and code change must follow these
rules.

1. Introduce one conceptual layer at a time.
2. Define a new term when it first appears. Do not use a list of unexplained future
   terms as if naming them explains them.
3. State what problem is being solved before presenting the mechanism.
4. Connect every assembly instruction or code construct to the CPU or memory
   behavior it causes.
5. State prerequisites explicitly and link back to the lesson that established
   them.
6. Separate required knowledge from optional historical or forward-looking notes.
7. Give exercises that can be solved using material already taught.
8. Use Mermaid for diagrams and use tables only for exact mappings or comparisons.
9. End with a precise boundary: what the reader can now explain and what has not
   yet been introduced.
10. Never trade clarity for compressed or clever code without explaining the
    tradeoff.
